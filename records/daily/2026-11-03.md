## 「明日の神奈川の天気」に答えられない問題（同日）

実機ログでは検索は 200 で返っていた（`神奈川の天気` → `明日の神奈川の天気` と言い換えて2回）。原因は2つ。

1. **モデルが 2 段目を呼ばない**。返した抜粋（Yahoo天気/tenki.jp/ウェザーニュース）は「よく当たる1時間毎のピンポイント天気…」のような宣伝文だけで、気温も降水確率も無い。それでも `fetch_page` に進まず「今は調べられない」と言っていた。
   → `web_search` の戻り値を JSON 配列から読みやすいテキストに変え、末尾に「具体的な数値が無ければ fetch_page で読む／同じ検索を繰り返さない」の NOTE を付けた。プロンプトも「数値が無ければ必ず1ページ読む・本文は最大2ページ」に変更。
2. **crawl4ai がナビしか返していなかった**。素の `markdown` は先頭 8000 文字がメニューで埋まり、天気表はその後ろ（tenki.jp は 21,745 文字中の後半）。しかも tenki.jp は気温を JS で描画するため HTML に `℃` が無い。
   → `scripts/crawl-server.py` で `PruningContentFilterLXML` の `fit_markdown` を使うように変更（ナビ除去、8031→8000 文字に収まる）。tenki.jp はこれでも数値が出ないが、ウェザーニュースは `℃` 6件と1時間毎の表が取れる。

実測: `POST /md {"url":"https://weathernews.jp/onebox/tenki/kanagawa/"}` → 1.3s / 8000文字 / `℃` 6件。

残る弱さ: 表が Markdown 変換で箇条書きに潰れて列名（気温・降水ミリ）が消える。モデルは前後の要約文から読めるが、精度は高くない。天気を確実にするなら Open-Meteo 等の API ツール追加が本筋（P23 で判断）。
