## 着手順

```
[今]  P10 の残り（実素材＋P8 の感情タグ）
        └ 2D 配線・3D 撤去は済（Avatar2D.tsx / avatar2dState.ts / scripts/test-avatar2d.mjs）
[次]  P14 / P15（テスト基盤・CI/CD）← ポートフォリオの核
        └ ただし P14 を「後回し」にするのは禁止。各機能の実装時にテストを1つ同行（D-006）
[後]  P11（Go+PostgreSQL）→ P12（履歴永続化）→ P13（長期記憶）
[終]  P16（負荷・長時間・前後比較）
```

理由:

- **P10 が先**: 2D 化は「見た目」だけだが、キャラ描画の手間をここで確定させないと P8 の土台が定まらない。2D 方式（自前 SVG/スプライト / Live2D / Rive）を決めないまま P8 に着手すると二重実装になる。
- **P14/P15 を「核」に置く**: 要件 5・8（品質・信頼性・CI/CD）は Mirage の成果提示の中核。ここが未着手だと「動くデモ」のまま終わる。P15 の完了条件は「ワークフローを作った」だけでは足りず、CI が実際に test/ビルド/デプロイを動かして確認済みであること。
- **P14 を一括後置きしない**: バックエンド実装後にテストを足すと、API/DB を含む結合度の高い部分ほどテストが遅れる。差分ごとにテストを付ける（D-006）。
- **P11〜P13 は後**: 長期記憶は保存方式が決まってから。先に API 境界（枠組み）を作り、その上に永続化と記憶を載せる。
