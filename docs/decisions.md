# 設計判断（正本）

> **有効な決定だけをここに置く。** 過去の決定・撤回された案は [history.md](../records/history.md) に残す（そちらは記録であり指示ではない）。
> 形式: 決定 / 理由 / 不採用案 / 影響範囲。追加時は日付と ID を必ず付ける。決定を変更したら、古い内容は history.md へ移す。


## D-001 実装対象は mirage-v2（このリポ）

- **決定**: 実装対象は `mirage-v2`（https://github.com/neotyaso/mirage-v2）。旧 `mirage` リポ（https://github.com/neotyaso/mirage、展示運用用）は参考資料として残し原則触らない。
- **理由**: 2026-09-23 の決定「完全自立型は新規リポで作る」。`mirage-v2` は `mirage` の履歴をクローンしてできたので、旧設計・学び・コミット歴がそのまま追える。
- **不採用案**:
  - (a) 旧 `mirage` でそのまま改善する → 展示運用と新規開発が混線し、「過去の記録」と「現在の仕様」が同じファイルに混ざる。
  - (b) 完全に空のリポから作り直す → 9 ヶ月分の実装と学びを捨てる。clone 一本に解決した。
- **影響**: 旧 `mirage` の md に書かれた過去の決定は**指示として読まない**。正本は `docs/decisions.md` と `docs/requirements.md`。


## D-002 キャラクター表現は 2D（3D は撤去）

- **決定**: キャラクターは 2D 中心。`src/components/Avatar.tsx` の VRM / Three.js による 3D 表示は移行後に撤去する。P8「声と体の連動」も 2D 前提で実装する。
- **理由**: 要件 3-1。3D の作り込み工数を AI・バックエンド・テスト・運用に回す。見た目の作り込みより技術面の成果を出す。
- **不採用案**:
  - (a) 3D 継続＋モデル刷新（Modal / TRELLIS.2 / Hunyuan2.1）→ 工数大。ポートフォリオの軸（品質・信頼性・CI/CD）が出ない。
  - (b) text-to-motion で全て生成 → 即応性・費用・失敗時の縮退が弱い。プリセット主体（既存 P8 の主）で行く。
- **未決**: 2D の実装方式（自前 SVG/スプライト、Live2D、Rive 等）は P10 着手時に「工数最小・表情の出しやすさ」で 1 つだけ選ぶ。並列に増やさない。


## D-003 Go + PostgreSQL の採用範囲は「会話 API ＋ 永続化」だけ

- **決定**: バックエンドは Go、DB は PostgreSQL。Go が担うのは会話 API・会話管理・永続化。**カメラ制御・顔検出・音声入出力・描画はブラウザのまま**（無理に Backend へ移さない）。
- **理由**: 要件 4。並行処理・API 設計・エラー処理・運用の学びをここで得る。ブラウザ側 API（カメラ・マイク・WebAudio）をバックエンド化しても意味が薄い。
- **不採用案**:
  - (a) Next.js へ全面移行 → 技術選定だけを理由の移行は不要。既存 React アプリの継続利用を優先。
  - (b) Node/BFF のみ → バックエンド強化という目的に反する。
- **影響**: P11 → P12 → P13 の順。


## D-004 フォールバック を維持（Gemini 一本化しない）

- **決定**: `Gemini → ローカル/縮退` の 2 層を維持。
- **理由**: 展示運用でオフライン/障害時に無音にならないため。既に実装済（3 リトライ→切替→バナー→手動復帰）。
- **不採用案**: Gemini 一本化（2026-09-23 の当初案。2026-09-29 に撤回済み）。
- **影響**: 要件 5「障害対応」の受け皿。ここをテスト（P14）で固める。


## D-005 最終目標は「駅・施設の困りごと案内」

- **決定**: 呼び込み（通行人への声かけ）はしない。置いておけば勝手に人を助ける案内エージェント。近づいた人に用件を聞き、前後の文脈を踏まえて答える。
- **理由**: 2026-09-30 の方向転換。3 本柱＝映像理解 / 会話記憶 / 優しい UI。
- **不採用案**: 完全自立型呼び込み（P4 声かけポリシーは破棄）。
- **影響**: P7（文脈ある第一声）は案内用途に転用検討。


## D-006 テストは機能実装と同時に入れる（P14 の完成を待たない）

- **決定**: テスト基盤の完成を待たず、各機能の実装時点から最低 1 つのテストを付ける。CI 上でテストが落ちたらマージ不可。
- **理由**: P14 を後回しにすると、バックエンド（P11/P12）を実装してからテストをまとめて追加することになり、API/DB を含む結合度の高い部分ほどテストが遅れる。差分ごとにテストが付くと PR の差分がそのまま検証可能になる。
- **不採用案**: 「バックエンド完成 → テスト一括追加」（現 P14 の前身案）。
- **影響**: 着手順は「P14 一括後置」ではなく「各機能にテスト同行」。


## D-007 3D モデル刷新は破棄

- **決定**: `scripts/gen3d_modal.py` は作らない。Modal 無料枠 / TRELLIS.2 / Hunyuan2.1 案は打ち切り。
- **理由**: D-002 の帰結。旧 `mirage` の TripoSG パイプラインは参考資料（[portfolio.md](../records/portfolio.md) 参照）。
- **影響**: なし（未着手のため削除するものが無い）。


## D-008 Next.js は現時点必須でない

- **決定**: 管理画面・公開 Web サイト等の必要性が明確になった段階で検討する。今は React + Vite のまま。
- **理由**: 技術選定だけを理由に既存アプリを移行しない。


## D-009 薄い記憶層 OSS は別リポ候補（本リポ外）

- **決定**: セッションをまたぐ薄い記憶層（mem0 / Letta / Zep の調査→必要なら自作）は `mirage-v2` のコードには入れない。独立リポで育てる。
- **理由**: コーディングエージェントのコンテキスト保持が目的。Mirage の会話履歴（P5 の服装キャッシュ等）とは別物。
- **設計方針（参考）**: JSONL 追記＋終了時要約＋次回注入だけ。重い DB・ベクトル検索は持たない。調査自体が Zenn ネタ。
- **影響**: P13（長期記憶）は本リポ内。汎用の記憶レイヤーはこの別リポ。

## D-011 2D キャラクターは自前 SVG ＋ CSS 変数（差し替え前提）

- **決定**: 2D は自前の SVG シルエットで描画し、状態は純関数 `src/components/avatar2dState.ts` に分離する。描画側は rAF から CSS 変数（`--blink` / `--mouth` / `--gaze-x` / `--par-x`）へ流すだけで、React の再描画を伴わない。実素材（画像/動画）は差し替え前提。
- **理由**: D-002 の「工数最小」を優先。状態を純関数にしておくとブラウザ無しでテストできる（`scripts/test-avatar2d.mjs`）。P8 の感情タグは「CSS 変数/レイヤーの差し替え」で済む。
- **不採用案**: Live2D Cubism / Rive → ライセンス・ツール・素材作成の工数が大きい。**表情差の作り込みが問題になったときに再検討**。
- **影響**: P10 は「配線まで」完了。残り＝実素材と P8 の感情タグ。D-002 の 2D 方針自体は変更なし。
